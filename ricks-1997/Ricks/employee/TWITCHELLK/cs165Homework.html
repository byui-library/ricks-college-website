03 Statistical Process Control Design
150 points
     Statistical Process Control (SPC) is a quality control technique typically used to monitor a manufacturing process. One goal of SPC is to detect changes in the manufacturing process. Early detection of process changes enable operators to take corrective action before "bad" product is created. A common SPC approach is to plot data on an average (X-bar) and range (R) chart. The chart is monitored for out-of-control conditions. (Additional information is available at the Common Control Chart Cookbook.)
     The first step to creating an X-bar (average) and R (range) chart is to gather data regarding how the process is currently operating. Sample measurements are taken and averaged to determine an X-bar value. This group of sample measurements is referred to as a sample subgroup. The difference between the largest and smallest values in a sample subgroup determines the corresponding R value. Typically there are three to five sample measurements in a sample subgroup. This homework assignment uses five.
     A minimum of twenty sample subgroups are used to determine the overall process average (X-double bar) and average range (R-bar). X-double bar is the average of the subgroup averages. R-bar is the average of the ranges. This homework assignment uses 25 sample subgroups. These data are also used to determine upper- and lower-control limits. It is expected that each X-bar and R value falls within these control limits. An X-bar or R value that falls outside of the control limits signals an out-of-control condition.
     The distance between the average (X-double bar or R-bar) and a control limit is divided equally into three zones. The zone closest to the average is referred to as zone C. (Please note the correction from zone A to zone C.) The next zone moving out from the average and toward the control limits is referred to zone B. The zone closest to the control limits (and most distant from the average) is referred to as zone A. (Please note the correction from zone C to zone A.) The locations of X-bar and R values in these zones are used to determine out-of-control conditions.
     Design software to "set up" an X-bar and R chart and then report out-of-control conditions. Your design shall consist of pseudocode as described in Software Design.
  1. Determine X-bar and R for each of the 25 subgroups in /home/twitchellk/examples/spc0.txt. You will use the code in /home/twitchellk/examples/readSPC0.cpp to read the data values into your program. Incorporate what this code does into your design.
  2. Using the calculated X-bar and R values, calculate X-double bar and R-bar.
  3. Using the calculated X-double bar and R-bar, calculate the upper and lower control limits (UCL and LCL) for both the averages (X-bar) and ranges (R). Note that the values of the constants in the following equations vary with the number of samples in the subgroup. These constants should not be used if the number of samples in the subgroup is something other than five.
    • X-bar UCL = X-double bar + (0.577 * R-bar)
      X-bar LCL = X-double bar - (0.577 * R-bar)
    • R UCL = 2.114 * R-bar
      R LCL = 0.0 * R-bar
  4. Process the data values in /home/twitchellk/examples/spc1.txt and report out-of-control conditions. Out-of-control conditions apply to both averages and ranges. You will use the code in /home/twitchellk/examples/readSPC1.cpp to read the data values into your program. Incorporate what this code does into your design. Out-of-control conditions include the following:
    • Fifteen consecutive values in zones C; no zones A or zones B values in this interval.
    • For any five consecutive values, four values are in zones B or beyond. The first value in this series is in zone B or beyond.
    • For any three consecutive values, two values are in zones A or beyond. The first value in this series is in zone A or beyond.
    • A run of seven consecutive values up or down.
    • A run of consecutive eight values all greater than or all less than X-double bar or R-bar.
    • A series of five consecutive values alternating above and below X-double bar or R-bar.
    • A value outside the control limits.
    • Clarification: if a value falls on the boundary line between zones, count it as belonging to the zone closest to the average. Thus a value on the boundary line between zones C and B would be counted as belonging to zone C. A single value on the control limit line, either upper or lower, is not counted by itself as being out-of-control.
  5. Process the following values as integers. Round values; do not truncate. Do not round intermediate values.
    • Round each X-bar value.
    • Round X-double bar and R-bar.
    • Round each UCL and LCL.
    • Round zone values. Calculate the zone values from the center line (X-double bar or R-bar).
  6. Report each out of control condition in the order in which first detected.

15 Bank
250 points
     Build an object-oriented program to process a list of bank transactions. Transactions include creating accounts, making deposits and withdrawals, adding accumulated interest, and deducting accumulated fees.
     The following rules apply:
  • A bounced check costs $25 and is deducted immediately from the checking account balance.
  • There is a fee for each check (checking account withdrawal). Each checking account may use a different fee. The fees are charged as part of an update (see below).
  • Savings accounts accrue interest. Each savings account may have a different interest rate. Interest is credited as part of an update (see below).
  • Interest is charged for loans. Each loan may have a different interest rate. Interest is charged as part of an update (see below).
  • An attempt is made to withdraw more money than is available in a savings or checking account shall be rejected and a message indicating such shall be output.
  • There is no maximum limit on the amount loaned.
     The transaction file uses the following symbols: s, c, l, t, and u.
  • s - Create a new savings account. An account number, a name, an initial balance, and the interest rate are supplied.
  • c - Create a new checking account. An account number, a name, an initial balance, and the fee for each processed check are supplied.
  • l - Create a new loan account. An account number, a name, an initial balance, and the interest rate are supplied.
  • t - Perform a transaction. An account number and the amount of the transaction are supplied.
    • For savings accounts, a positive value is a deposit and a negative value is a withdrawal.
    • For checking accounts, a positive value is a deposit and a negative value represents a check.
    • For loan accounts, a positive value represents a payment on the loan and a negative value represents the borrowing of additional money.
  • u - perform an update. An account number is supplied.
    • For savings accounts, calculate and add interest earned.
    • For checking accounts, calculate and deduct the fee for each check.
    • For loan accounts, calculate and add the interest charged to the outstanding loan balance.
     Use the list of transactions contained in /home/ket/examples/bank.txt. Use C++ file I/O to process this file. There is no user input. All transactions shall be processed in a single loop.
     Create a base class named Account. Created derived classes named Savings, Checking, and Loan.
     The output from your program shall exactly match the output contained in /home/ket/examples/bankOutput.txt.
